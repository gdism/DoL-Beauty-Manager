# 桌面资源与响应性实测

2026-10-18，Windows 桌面、本机 HTTP、独立无头浏览器配置。Chrome 155.0.8059.84，Edge 152.0.4191.66。原宿主及固定840图样本均为任务内副本，测试拦截外网。每个浏览器各一次测量，不能外推至 Android、其他机器、全部包或桌面 file 模式。

测量构建 SHA-256：`1201921550278ff0e107fae3fcedb8c60ea9280bc2cab6209a58a04f799d2e13`。其后补充了“全坏图来源仍检查代码依赖”的门禁；此表保留实际测量构建，未将历史指标改称最终包结果。

## 相同840图流程

| 阶段 | Chrome耗时 | Edge耗时 | 两者最长观测主线程任务 |
|---|---:|---:|---:|
| ZIP导入与扫描 | 510 ms | 536 ms | 未记录到≥50 ms任务 |
| 认证规则修复 | 451 ms | 431 ms | 64 / 70 ms |
| 应用与保存 | 309 ms | 210 ms | 未记录到≥50 ms任务 |
| 完整ZIP生成与摘要 | 324 ms | 323 ms | 未记录到≥50 ms任务 |
| 撤销 | 106 ms | 101 ms | 未记录到≥50 ms任务 |

输入图片字节共3,424,017，准备后图片字节共3,423,825。ZIP生成在浏览器内完成，计时包括摘要计算；不包括浏览器下载落盘或将整包传回自动化工具的传输时间。导入扫描同时读取宿主来源，因此耗时也包含宿主检查。

首次测量发现导入/修复分别有约858–879 ms主线程任务，CPU采样定位于版本识别。改为只提取白名单源码、单次匹配共享摘要后，同机复测最长观测任务降至64–70 ms。每次匹配仍重读源码与passage；源码或passage变化使匹配失效的测试通过。原始失败及优化前记录保留在任务内。

## 内存口径与未测项

CDP约每100 ms采样JS堆，观测最大值 Chrome 315.1 MiB、Edge 202.0 MiB。数值包括游戏宿主、Mod及本工具；受GC时机影响，未归因到单个功能。该采样不含完整浏览器进程、图片解码/GPU缓冲，也可能遗漏短暂峰值，因此**不是总峰值内存**，不能用它宣布内存上限或优化幅度。

50 ms心跳的最大观测额外延迟：Chrome 64.0 ms、Edge 52.9 ms。未记录到长任务仅表示本次观察窗口中没有对应条目，不代表永不卡顿。规则PNG处理仍可能产生约70 ms任务，更大图片与包需要进一步预算。

现有输入保护为单资源32 MiB、PNG预检及解码后32M像素、累计读取512 MiB；ZIP另有展开限制。这些是防止无界输入的工程保护，不是经过验收的推荐包体、移动端支持阈值或可用保证。尚缺完整进程/图像缓冲峰值、其他三版、file模式资源指标与Android实测。

原版基线18735图的实际导入、逐图摘要校验、离线缓存及回退另有功能测试；本表不包含其性能测量。
